# Myhrvold et al. 2015 — Amniote_Range_Count_Aug_2015.csv

## Source
Myhrvold, N. P., Baldridge, E., Chan, B., Sivam, D., Freeman, D. L., & Ernest, S. K. M. (2015).
An amniote life-history database to perform comparative analyses with birds, mammals, and
reptiles. *Ecology*, 96(11), 3109. https://doi.org/10.1890/15-0846R.1 (Ecological Archives E096-269)

## What this item is
For every species row and trait in the Amniote Life-History Database, the **minimum**, **maximum**
and **number of underlying literature records** behind the single value published in
`Amniote_Database_Aug_2015.csv`. It is the dispersion-and-sample-size layer of the database: the
value item tells you *what* was compiled, this one tells you *from how many records and over what
range*.

- 21,322 species rows × 28 traits in the published wide file
- **107,605 rows** in the long analysis table (one row per species × trait with `count > 0`)
- 21,322 binomials; classes Aves, Mammalia, Reptilia

## Frozen source — digital-native, bytes untouched
`Myhrvold_etal_2015_AmnioteRangeCountAug2015_snapshot.csv` is a copy-rename of
`Data_Files/Amniote_Range_Count_Aug_2015.csv` with the bytes unchanged — not opened, not re-saved,
not converted. Verified: md5 `8095602c7d10befc52feaf22db8e6c76` on both.

## Build
`Myhrvold_etal_2015_AmnioteRangeCountAug2015.csv.R` (R, matching the repo house dialect and the
three other `.R` scripts in this folder; the one `.py` here builds the value item). It pivots the
`min_*` / `max_*` / `count_*` triples to long, drops `count == 0` cells, attaches units from the
paper's own `Supplemental_Table_9_Dataset_Field_Information.csv`, and renames the published
`classx` / `orderx` / `familyx` to `class` / `order` / `family` to match the sibling items.

### A naming inconsistency in the publication
This file drops the unit suffix the database uses (`female_maturity` vs `female_maturity_d`). One
trait does not follow even that rule: it is `hatching_svl` here but `birth_or_hatching_svl_cm` in
the database, while its weight counterpart is `birth_hatching_weight` in both. The build declares
that single alias and asserts every other trait maps 1:1 onto a Supplemental Table 9 field. The
database trait `longevity_y` has no min/max/count triple here.

## Errata — 21 cells, one mechanism
21 cells, **all** `female_svl`, print `count > 0` and a real `max` but `min = -999`, the missing
sentinel. The mechanism is demonstrable: the publication computed `min()` and `count()` over the
record pool **with the −999 sentinel included as if it were an observation**. For all 21 cells the
published `count` equals the number of real records in `Amniote_Sparse_Table_Aug_2015.csv` plus
one, and the published `max` reproduces the true maximum exactly.

Recorded as `Myhrvold_etal_2015-E003` … `-E023` in
`reference_tables/Myhrvold_etal_2015_errata.csv`, `issue_type = publication_error`, status
`proposed`, each with the recoverable true minimum as `proposed_value`. Per the errata convention
the printed value stands: `min` is carried as blank here and the printed `count` is unchanged. The
build asserts the anomaly still matches exactly those 21 female_svl cells and stops if it does not.
