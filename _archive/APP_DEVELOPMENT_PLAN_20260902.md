# Evo-M1 Portal Development Roadmap

## Overview

The Evo-M1 Portal will be developed as a single Shiny application containing multiple tabs that provide complementary views of the Evo-M1-Trait-Data repository.

Rather than maintaining separate applications, a unified portal will allow users to move seamlessly between data discovery, comparative analysis, and specimen provenance while sharing common infrastructure and data-loading functions.

## Rationale

The repository contains both source-level data and curated species-level compilations.

These represent different stages of the data lifecycle and serve different purposes:

- Source-level data preserve the original measurements, metadata, specimen identifiers, publications, and provenance.
- Compiled datasets generated by the `__merging_*` workflows are designed for comparative analyses and visualization.
- Not all source-level observations are represented in the compiled datasets.
- Therefore, the application should clearly distinguish between exploratory analyses based on compiled datasets and source-level data exploration.

## Proposed Architecture

The portal will consist of three primary modules.

### 1. Data Directory

The Data Directory serves as the entry point to the repository and provides a searchable catalogue of available data resources.

#### Objectives

- Browse available traits.
- Browse anatomical structures.
- Browse datasets.
- Browse source publications.
- Browse taxonomic coverage.
- Provide data provenance information.
- Facilitate dataset discovery.

#### Example Questions

- Which studies measured cerebellar volume?
- Which traits are available for gorillas?
- Which publications include motor cortex measurements?
- Which datasets contain cell-count estimates?

#### Data Sources

Potential sources include:

- `_keys/`
- metadata registries
- source catalogs
- trait inventories
- dataset-level summaries
- project documentation

---

### 2. Trait Explorer

The Trait Explorer provides comparative visualizations using compiled species-level datasets.

#### Objectives

- Generate scatterplots for any two traits.
- Compare species across clades.
- Explore evolutionary patterns.
- Export figures and data.

#### Functionality

- Select x-axis trait.
- Select y-axis trait.
- Filter by taxonomy.
- Highlight species.
- Display regression models.
- Export plots.
- Export filtered datasets.

#### Important Note

Trait Explorer operates on curated outputs from the repository's compilation workflows and should not be interpreted as representing all source-level observations available in Evo-M1-Trait-Data.

A clear statement should be displayed within the application:

> Trait Explorer uses curated compiled datasets and may not contain every source-level measurement available in the repository.

---

### 3. Specimen Tracker

The Specimen Tracker provides specimen-centric exploration and provenance tracking.

#### Objectives

- Search for individual specimens.
- Track specimen reuse across studies.
- Identify overlap among publications.
- Support provenance audits.
- Support dataset quality-control workflows.

#### Search Types

- Specimen identifier.
- Collection identifier.
- Species name.
- Publication.
- Dataset.

#### Outputs

- Canonical specimen identity.
- Species.
- Collection.
- Source datasets.
- Publications.
- Measured traits.
- Provenance history.
- Reuse across studies.

#### Example Use Cases

- Determine how many studies include a particular chimpanzee specimen.
- Identify publications that reused specimens from an earlier study.
- Determine which traits were measured for a given individual.

## Development Phases

### Phase 1: Modularization

Refactor the existing scatterplot application into a modular framework capable of supporting multiple tabs.

Deliverables:

- Modular app structure.
- Shared data-loading functions.
- Shared navigation framework.

### Phase 2: Data Directory

Implement the Data Directory module.

Deliverables:

- Dataset catalogue.
- Trait catalogue.
- Publication catalogue.
- Search and filtering tools.

### Phase 3: Specimen Tracker

Implement specimen-level provenance tracking and search capabilities.

Deliverables:

- Specimen search.
- Publication linkage.
- Dataset linkage.
- Provenance summaries.

### Phase 4: Integration

Connect all modules within a unified workflow.

Example navigation:

```text
Data Directory
      ↓
Available Trait
      ↓
Trait Explorer
      ↓
Species
      ↓
Specimen Tracker
```

## Long-Term Goal

The Evo-M1 Portal should become the primary interface for interacting with Evo-M1-Trait-Data by providing:

1. Data discovery.
2. Comparative visualization.
3. Specimen provenance tracking.
4. Quality-control support.
5. Transparent access to source and compiled data products.
