# `taxon_clarity.csv` — how determinate is the printed name, and what do we infer

Per source, two separate questions about a species name:

1. **How clear is the taxon as printed?** Does the string name one extant
   animal, or does it leave the subspecies, the domestication status, or the
   species itself unstated?
2. **What do we infer the animal to be**, with what confidence and on what
   evidence?

These are deliberately separate columns. A name can be perfectly clear and
still be wrong (a re-identification); a name can be vague and still be
confidently inferable. Collapsing the two is what makes existing keys hard to
audit.

## Relationship to the keys that already exist

| file | answers |
|---|---|
| `<Collection>/species_key.csv` | variant spelling → `accepted_name` (identity) |
| `reidentifications.csv` | "this source names taxon A but the specimen is taxon B" |
| `specimen_crosswalk/taxon_concept_registry.csv` | what a *name* meant in a period (`s.l.`/`s.s.`, decomposability) |
| `volumes_species_overrides.csv` | forced `accepted_name`, volumes merge only |
| **`taxon_clarity.csv`** | **how precise a source's printed name is, and what we infer from it** |

None of the others record *precision*. That is the gap this fills, and it is
what you need in order to decide pooling questions on evidence rather than by
feel — see `TAXON_POOLING_DESIGN.md`.

## Two files, one generated and one curated

- **`taxon_clarity_observed.csv`** — generated by
  `python3 _keys/build_taxon_clarity_observed.py`. One row per
  `(source_publication, printed_name)` across every `__merging_*` long file
  that carries a `species_printed` column (20 of them): the printed string,
  the tables it appears in, the value count, and `resolves_to`. Observation
  only; no judgement. Currently **10,681 pairs, 7,575 distinct printed names**.
- **`taxon_clarity.csv`** — hand-curated judgements. A judgement needs a
  stated basis and an author, and a script has neither, so nothing writes this
  file.

`resolves_to` is the column to read first. Where it holds more than one value
the *same* printed string is being resolved two ways **within a single
merge** — which is a defect, not a policy difference. The worked case is
`Gorilla gorilla` in `__merging_endocranial_volume`: one row becomes
`Gorilla gorilla` (ECV 490.41, `species_basis = hub`) and another becomes
`Gorilla sp.` (ECV 461.0, `species_basis = lump`), from the same printed
name in the same merge.

Divergence *between* merges is a separate matter and is visible by reading
the per-merge files rather than this column: six merges (GLI, behaviour,
cell_morphology, cellcounts, gyrification, weights) keep `Gorilla gorilla`,
while `__merging_volumes` lumps all 110 of its rows to `Gorilla sp.` as a
stated policy. That is deliberate; the internal split above is not.

## Columns

`source_publication` is the paper (house convention: key by paper, not table).
**`*` means "every source printing this name"**, and a row naming a specific
paper overrides the wildcard. That keeps the file small — one row covers the
26 papers printing `Gorilla gorilla`.

| column | meaning |
|---|---|
| `printed_name` | the string as printed, verbatim |
| `printed_rank` | what rank the string asserts: `genus` / `species` / `subspecies` / `form` |
| `taxon_clarity` | one of the six classes below |
| `clarity_basis` | the evidence for that class — **required** |
| `inferred_accepted_name` | what we infer the animal to be; blank if not inferable |
| `inference_confidence` | `high` / `medium` / `low` |
| `inference_basis` | evidence for the inference — required if a name is inferred |
| `inference_authority` | `MDD` / `NCBI` / `verbatim` / `our_judgment` / … |
| `ambiguity_affects` | **which traits the ambiguity actually changes**, or `none` / `all` |
| `decided_by`, `decided_date`, `note` | provenance |

### Clarity classes

- `determinate` — names one extant taxon; nothing to infer.
- `subspecies_unstated` — species rank given, subspecies not.
- `domestication_unstated` — species given, wild vs domestic not.
- `pre_split` — referent spans more than one modern taxon; cross-reference
  `taxon_concept_registry.csv`.
- `genus_indet` — genus or bare common name only.
- `disputed` — sources conflict on identity.

`ambiguity_affects` is the column that makes this actionable. Vagueness is
not uniformly harmful: for the ferret, `Neocortex_grey_matter_Vol.mm3` is
identical under both labels while body mass differs by 50%. Recording *which*
traits an ambiguity touches means a downstream user can ignore it for the
traits it does not reach.

## What is seeded

11 rows, covering the four genera that prompted the file plus three
indeterminate names the enumerator turned up. That is **0.8% of values** —
the register is a scaffold, not a survey, and
`_checks/check_taxon_clarity.py` prints the highest-value unjudged pairs as a
worklist on every run.

The two rows worth reading as worked examples:

**The ferret.** `Bush_Allman_2003_Table1` prints `Mustela putorius`;
`Bush_Allman_2004_a_Table2` prints `Mustela putorius furo`. Both report
`Neocortex_grey_matter_Vol.mm3 = 2140`. One lab published one specimen under
both names in consecutive papers, so the bare binomial there denotes the
domestic ferret — positive evidence that the two ferret labels are one
animal. The two labels otherwise draw on completely disjoint source sets,
which is why their body masses disagree by 50% without either being wrong.

**The pig.** Four papers print the bare `Sus scrofa` — Haarlem 2026 (critical
flicker fusion), Heffner & Heffner 1992a (hearing), Koay 1998 (hearing),
Veilleux & Kirk 2014 (vision). All four are laboratory psychophysics, which
uses domestic animals; none states the form. Confidence is `medium`, not
`high`, precisely because none of them says so. If it is confirmed per paper,
the right fix is to correct the labels at source, not to pool wild and
domestic downstream.

## Open problems the enumerator found

- **`macaque` resolves to both *Macaca fascicularis* and *Macaca mulatta***
  inside `__merging_GLI`. Two different species currently carry values derived
  from one indeterminate label. Blocking.
- **302 unjudged pairs print a single word** — `sheep` (252 values),
  `Kudu`, `Rat`, `Human`, `Giraffe`. Some resolve (`sheep` → *Ovis aries*),
  some never do (`Kudu` stays `Kudu` as the species value).
- **11 unjudged pairs resolve more than one way.** Nine are in
  `__merging_cell_morphology`, where the same common name sometimes resolved
  to a binomial and sometimes stayed as the common name — a resolution gap,
  not a taxonomy question. Two are *Pongo*, which the concept registry
  already flags as `pre_split`.

## Usage

```
python3 _keys/build_taxon_clarity_observed.py   # regenerate observations
python3 _checks/check_taxon_clarity.py          # validate + coverage report
```

The check exits non-zero on a malformed register — an unknown clarity class,
an empty `clarity_basis`, an inference with no basis/authority/confidence, or
a `determinate` row whose inferred name differs from the printed one (that is
a re-identification and belongs in `reidentifications.csv`). An *incomplete*
register is not an error: 10,681 pairs will not be judged by hand.
